# ⚡ parselog CLI — 开发者极速全链路日志与性能分析诊断利器

一款针对 ERP / YES 平台研发人员量身打造的高性能全链路日志分析、方法级性能剖析与 SQL 架构诊断利器。基于 **Node.js 多核并行流式解析** 与 **DuckDB C++ 向量计算引擎** 构建，专门解决开发调优阶段 **全链路方法自耗时难定位、N+1 冗余循环隐蔽、慢 SQL 难抓取、日志文件定位繁琐** 的实际痛点。

---

## 🎯 解决开发调优的核心痛点

| 开发调优痛点 | 传统日志排查方式 | ⚡ parselog CLI 调优优势 |
| :--- | :--- | :--- |
| **全链路瓶颈难下钻** | 难以拆解请求中 Java 代码、宏脚本、SQL 和提交各自耗时 | **全链路方法剖析树 (ActionRecorder)**：精准还原以请求为根的树形方法调用链，一键计算**净自耗时 (Self Time)**，支持自耗时动态阈值过滤与高亮展开 |
| **隐蔽的 N+1 循环** | 代码循环体中多次调 SQL 很难通过自测发现 | **独家事务句柄级诊断**：基于 `dbManager` 事务对象，精准捕捉【同一事务内】的重复 SQL，给出重构建议，支持按 TraceID+事务连接 精准过滤 |
| **日志文件海量且大** | 大日志文件搜索缓慢，容易卡死 | **2.8 秒解析 50 万行 (57MB) 日志**，吞吐率达 **250,000+ 行/秒**，百万数据秒级装载与分析 |
| **日志定位繁琐** | 查出 SQL 后需手动对照文件名和行号翻看日志 | **一键直达日志文件精准行号 (`vscode://file/`)**，点击即可唤起 VSCode 打开日志文件并光标定位，支持 `.gz` 自动解压 |
| **全局请求聚合与宏观分析** | 难以纵览系统各业务请求的性能与 SQL 消耗全貌 | **Trace 聚合大盘**：按 TraceID 聚合分组，按【累计总耗时优先】排序，支持一键穿透至性能链路树、N+1 诊断与慢 SQL |
| **开箱即用体验** | 搭建复杂分析工具门槛高，影响开发节奏 | **零配置极轻量**：命令行单指令 `parselog .` 自动启动纯内存分析并拉起可视化控制台 |

## 🚀 1 秒快速开始

### ⚙️ 环境要求
- **Node.js**：`v24.0.0` 或更高版本（推荐 `v24+`）

---

### 1. 🌟 团队全局安装 (无需发布 npm)

在终端运行以下命令完成全局安装：

```bash
npm install -g git+https://github.com/believe-pxw/analyzeSqlLog.git --allow-git=all --allow-scripts=duckdb
```

### 2. ⚡ 命令行直接使用

在开发项目或日志目录下，终端直接运行：
```bash
parselog .
```
或者分析指定的日志目录 / 单个日志文件（同时支持 `.log` 文本日志及 `.log.gz` 压缩日志）：
```bash
parselog "D:\Users\boke\Desktop\source\bokeerp\erp-backend\logs"
```
*(注：原命令 `sqllog` 作为内置别名依然完全兼容可用)*

解析完成后，程序会自动在默认浏览器中打开可视调优控制台（默认 `http://localhost:3000`）。

> 📖 详细图文操作教程与实战排查案例，请参阅 **[用户图文实战指南 (docs/USER_GUIDE.md)](./docs/USER_GUIDE.md)**。

## 💡 七大开发调优视图

控制台提供结构化的七大核心视图，全面覆盖开发调优的全流程：

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 📌 顶部全局大盘: 链路总请求: 56 笔 | 最高单请求耗时: 69,196 ms | SQL 执行总耗时: 7,175 ms | SQL 执行总次数: 7,800 | 独立 Trace: 265 | 最高单条 SQL 耗时: 386 ms │
└────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
  │
  ├── ⚡ 1. 性能链路树 (Flame/Tree) ── 全链路方法级性能剖析树，自耗时动态过滤展开与四维正交归一大盘
  ├── 🌐 2. Trace 聚合大盘        ── 按 TraceID 聚合分组，累计总耗时降序排列，支持一键穿透
  ├── 🔁 3. 事务内重复 SQL (N+1)  ── 同一 dbManager 事务连接内循环诊断，精准抓取 N+1 隐患
  ├── 📊 4. SQL 频次榜            ── 全库 SQL 模板归一化统计，按总耗时/频次排行，支持查看调用
  ├── 🐢 5. 慢 SQL 排行           ── 单次耗时降序，提供日志绝对路径行号，一键直达 VSCode
  ├── 🔗 6. Trace 链路分析        ── 单次 Trace 内部所有 SQL 执行时间线无损还原
  └── 📋 7. SQL 调用明细          ── 指定 SQL 模板的全库/当前事务实例调用列表与行号定位
```

### 1. ⚡ 性能链路树 (Performance Profiler & Flame Hotspots)
- **四维正交归一耗时体系**：
  $$\text{请求总耗时 (100\%)} = \text{🟪 Java 业务纯计算} + \text{🟦 数据库 SQL} + \text{🟩 事务提交阶段}$$
  在 Java 业务卡片中清晰拆解 `根自耗时 + 各子方法净自耗时`，彻底避免数据重叠混淆。
- **⚡ 自耗时 (Self Time) 动态过滤展开与高亮**：
  - 支持在工具栏自由输入阈值：`⚡ 仅展开自耗时 >= [ N ] ms 的节点`；
  - 自动递归展开命中的祖先链路，命中节点以黄色背景（`#fef3c7`）高亮突出显示；
  - 提供 `⚡ 自耗时 > 50ms`、`⚡ 自耗时 > 10ms`、`🔥 总耗时 > 50ms` 快捷按钮。
- **自耗时彩色徽章与百分比进度条**：
  - 自耗时列提供分级彩色徽章（$\ge 500\text{ms}$ 🔴 红色、$\ge 50\text{ms}$ 🟡 黄色、$\ge 10\text{ms}$ 🟣 紫色、$< 10\text{ms}$ 🔵 浅蓝），横向进度条直观呈现单节点占请求总耗时的比例。
- **秒开分层渲染与 SQL 多列折叠**：
  - 默认展开 Level 0/1 顶层分支，深层分支按需瞬间秒开；
  - 复杂 SQL 自动压缩多列为 `select ... from table`，支持左键展开/折叠与右键一键复制完整 SQL。

### 2. 🌐 Trace 聚合大盘
- **总耗时优先排序**：按请求/TraceID 分组，第一排序字段为**累计总耗时 (`total_time_ms DESC`)**，第二排序字段为 **SQL 执行次数 (`sql_count DESC`)**。
- **全景指标展现**：汇总 SQL 执行次数、总耗时、平均耗时、最高单条耗时、事务连接数与首条执行时刻。
- **一键快捷分析**：每行提供「🔗 链路」、「🔁 N+1」、「🐢 慢SQL」操作按钮，一键带入该 TraceID 穿透至对应 Tab 展开深度分析。

### 3. 🔁 事务内重复 SQL (N+1) 诊断
- **精准事务粒度**：基于日志中的 `dbManager` 内存对象句柄（如 `MySqlDBManager@7b2aa7e0`），只抓取在【同一数据库事务内】重复调用的 SQL 模板，彻底排除跨请求/跨事务的误报。
- **自由手填阈值**：支持**自由手填重复次数阈值（`>= N 次`）**，实时动态筛选。
- **重构建议与下钻**：自动判定严重等级（如推荐 `IN(...)` 批量化或二级缓存），提供「🔍 查看调用」一键跳转至调用明细。

### 4. 📊 SQL 频次榜
- **全库归一化聚合**：自动对全库参数化 SQL 模板进行归一化频次与耗时统计，汇总全局执行总次数、总耗时、平均耗时、最大耗时与涉及 Trace 数。
- **下钻明细**：点击「🔍 查看调用」即可调出该模板在全库中的每一笔具体执行调用记录。

### 5. 🐢 慢 SQL 排行
- **耗时降序呈现**：按单次执行耗时降序排列，快速找出拖慢接口响应的瓶颈 SQL。
- **灵活阈值**：支持**自由手填耗时阈值（`>= N ms`）**与关键词过滤。
- **日志定位**：每一条慢 SQL 均提供 `📂 file:line` 链接，点击瞬间唤起 VSCode 打开对应的日志文件并精准跳转至该行。

### 6. 🔗 Trace 链路分析
- **全序列还原**：完整还原单次接口请求生命周期内的全部 SQL 执行序列（默认 50 条/页）。
- **原生时间顺序**：严格按日志真实时间顺序展示单次 Trace 的完整上下文流程。
- **行号与路径**：完整输出日志文件的绝对路径和所在行号，支持一键在 VSCode 中打开日志文件并高亮定位。

### 7. 📋 SQL 调用明细
- **全上下文追溯**：展示指定 SQL 模板在全库中的每一笔具体调用记录，顶部动态呈现过滤上下文标签（准确标注来源：频次榜或 N+1 诊断、TraceID、dbManager 事务句柄 Hash 及循环次数）。
- **行号与路径**：完整输出日志文件的绝对路径和所在行号，支持一键在 VSCode 中打开日志文件。

## ⚡ 性能与技术架构

- **C++ 向量执行**：底层依赖 **DuckDB 纯内存引擎**，全量数据在内存进行 Multi-row Chunk 向量化装载与聚合，查询耗时通常 $< 50\text{ms}$。
- **多核 Worker Threads**：面对超大日志文件或日志目录，自动启用多核子进程并行切块解析，充分吃满 CPU 性能。
- **智能列名折叠**：针对上百列的超长 `SELECT` 语句，前端 0ms 瞬间折叠为 `select ... from <表与条件>`，兼顾可读性与浏览效率。
