# ⚡ sqllog CLI — 开发者极速 SQL 调优与 N+1 诊断利器

一款针对 ERP / YES 平台研发人员量身打造的高性能 SQL 日志分析、链路追溯与架构诊断工具。基于 **Node.js 多核并行解析** 与 **DuckDB C++ 向量计算引擎** 构建，专门解决开发调优阶段 **N+1 冗余循环隐蔽、慢 SQL 难抓取、日志文件定位繁琐** 的实际痛点。

---

## 🎯 解决开发调优的核心痛点

| 开发调优痛点 | 传统日志排查方式 | ⚡ sqllog CLI 调优优势 |
| :--- | :--- | :--- |
| **隐蔽的 N+1 循环** | 代码循环体中多次调 SQL 很难通过自测发现 | **独家事务句柄级诊断**：基于 `dbManager` 事务对象，精准捕捉【同一事务内】的重复 SQL，给出重构建议 |
| **日志文件海量且大** | 大日志文件搜索缓慢，容易卡死 | **2.8 秒解析 50 万行 (57MB) 日志**，吞吐率达 **270,000+ 行/秒**，百万数据秒级装载与分析 |
| **日志定位繁琐** | 查出 SQL 后需手动对照文件名和行号翻看日志 | **一键直达日志文件精准行号 (`vscode://file/`)**，点击即可唤起 VSCode 打开日志文件并光标定位，支持 `.gz` 自动解压 |
| **单次请求 SQL 序列** | 难还原某次接口请求内部执行了哪些 SQL | **Trace 链路全序列**：按日志真实时间顺序还原单次请求生命周期内的完整 SQL 调用图谱 |
| **开箱即用体验** | 搭建复杂分析工具门槛高，影响开发节奏 | **零配置极轻量**：命令行单指令 `sqllog .` 自动启动纯内存分析并拉起可视化控制台 |

## 🚀 1 秒快速开始

### ⚙️ 环境要求
- **Node.js**：`v24.0.0` 或更高版本（推荐 `v24+`）

---

### 1. 🌟 团队全局安装 (无需发布 npm)

在终端运行以下命令完成全局安装：

```bash
npm install -g git+https://github.com/believe-pxw/analyzeSqlLog.git --allow-git=all --allow-scripts=duckdb
```

### 2. ⚡ 命令行直接使用

在开发项目或日志目录下，终端直接运行：
```bash
sqllog .
```
或者分析指定的日志目录 / 单个日志文件（同时支持 `.log` 文本日志及 `.log.gz` 压缩日志）：
```bash
sqllog "D:\Users\boke\Desktop\source\bokeerp\erp-backend\logs"
```
解析完成后，程序会自动在默认浏览器中打开可视调优控制台（如 `http://localhost:3000`）。

## 💡 六大开发调优视图

控制台提供结构化的六大视图，全面覆盖开发调优的全流程：

### 1. 🔁 事务内重复 SQL (N+1) 诊断 (默认首页)
- **精准事务粒度**：基于日志中的 `dbManager` 内存对象句柄（如 `MySqlDBManager@7b2aa7e0`），只抓取在【同一数据库事务内】重复调用的 SQL 模板，彻底排除跨请求/跨事务的误报。
- **自由手填阈值**：支持**自由手填重复次数阈值（`>= N 次`）**，实时动态筛选。
- **重构建议与下钻**：自动判定严重等级（如推荐 `IN(...)` 批量化或二级缓存），提供「🔍 查看调用」一键跳转至调用明细。

### 2. 🐢 慢 SQL 排行
- **耗时降序呈现**：按单次执行耗时降序排列，快速找出拖慢接口响应的瓶颈 SQL。
- **灵活阈值**：支持**自由手填耗时阈值（`>= N ms`）**过滤。
- **日志定位**：每一条慢 SQL 均提供 `📎 file:line` 链接，点击瞬间唤起 VSCode 打开对应的日志文件并精准跳转至该行。

### 3. 🔗 Trace 链路分析
- **全序列还原**：完整还原单次接口请求生命周期内的全部 SQL 执行序列（默认 50 条/页）。
- **原生时间顺序**：严格按日志真实时间顺序展示单次 Trace 的完整上下文流程。
- **行号与路径**：完整输出日志文件的绝对路径和所在行号，支持一键在 VSCode 中打开日志文件并高亮定位。

### 4. 📊 SQL 频次榜
- **全库归一化聚合**：自动对全库参数化 SQL 模板进行归一化频次与耗时统计，汇总全局执行总次数、总耗时、平均耗时、最大耗时与涉及 Trace 数。
- **下钻明细**：点击「🔍 查看调用」即可调出该模板在全库中的每一笔具体执行调用记录。

### 5. 📋 SQL 调用明细
- **全上下文追溯**：展示指定 SQL 模板在全库中的每一笔具体调用记录，顶部动态呈现过滤上下文标签（准确标注来源：频次榜或 N+1 诊断、TraceID、dbManager 事务句柄 Hash 及循环次数）。
- **行号与路径**：完整输出日志文件的绝对路径和所在行号，支持一键在 VSCode 中高亮打开日志文件。

### 6. 📈 概览统计分析
- 汇聚分析 SQL 总数、归一模板数、最高慢 SQL 耗时、独立 Trace 动作数、总耗时以及文件扫描解析性能指标。

## 🛠️ 典型开发调优工作流

1. **上线前 N+1 自查**：功能开发完成后，在本地跑一遍流程，打开 `🔁 事务内重复 SQL (N+1) 诊断` 面板，检查是否存在未做批量化的循环查库逻辑。
2. **慢接口 SQL 专项治理**：针对响应慢的接口，在 `🐢 慢 SQL 排行` 或 `🔗 Trace 链路分析` 中找出高耗时 SQL，点击 `📎 file:line` 链接直接拉起 VSCode 打开对应的日志文件定位分析。
3. **高频热点 SQL 优化**：在 `📊 SQL 频次榜` 查看被高频调用的 SQL 模板，评估增加二级缓存或优化索引。

## ⚡ 性能与技术架构

- **C++ 向量执行**：底层依赖 **DuckDB 纯内存引擎**，全量数据在内存进行 Multi-row Chunk 向量化装载与聚合，查询耗时通常 $< 50\text{ms}$。
- **多核 Worker Threads**：面对超大日志文件或日志目录，自动启用多核子进程并行切块解析，充分吃满 CPU 性能。
- **智能列名折叠**：针对上百列的超长 `SELECT` 语句，前端 0ms 瞬间折叠为 `select ... from <表与条件>`，兼顾可读性与浏览效率。
