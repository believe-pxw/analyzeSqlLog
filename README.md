# ⚡ sqllog CLI — 极速 SQL 日志分析与 N+1 诊断利器

一款针对 ERP / YES 平台深度定制的高性能 SQL 日志分析、Trace 链路追踪与 N+1 循环诊断工具。基于 **Node.js 多核并行解析** 与 **DuckDB C++ 向量计算引擎** 构建，解决海量应用日志排查难、慢查询隐蔽、N+1 冗余循环深的研发与运维痛点。

---

## 🔥 为什么选择 sqllog？

| 核心特性 | 传统日志排查方式 (grep / txt) | ⚡ sqllog CLI 优势 |

| **代码/日志定位** | 需人工对照文件名和文本翻找 | **一键直达源码与日志行号 (`vscode://file/`)**，支持 `.log.gz` 压缩包秒级解压跳转 |

| **部署与使用** | 需搭建复杂 ELK / 数据库服务 | **零配置轻量化**：命令行单指令 `sqllog .` 自动启动 DuckDB 纯内存分析并拉起 UI |

## 🚀 1 秒快速开始

### ⚙️ 环境要求
- **Node.js**：`v24.0.0` 或更高版本（推荐 `v24+`）

---

### 1. 🌟 团队全局安装 (无需发布 npm)

在终端运行以下命令完成全局安装：

```bash
npm install -g git+https://github.com/believe-pxw/analyzeSqlLog.git --allow-git=all --allow-scripts=duckdb
```

### 2. ⚡ 命令行直接使用

在任意存放日志的目录，终端直接运行：
```bash
sqllog .
```
或者分析指定的日志目录 / 单个日志文件（同时支持 `.log` 文本日志及 `.log.gz` 压缩日志）：
```bash
sqllog "D:\Users\boke\Desktop\source\bokeerp\erp-backend\logs"
```
解析完成后，程序会自动在默认浏览器中打开可视分析控制台（如 `http://localhost:3000`）。

## 💡 六大核心功能面板

控制台提供结构化的六大视图，全面覆盖 SQL 性能分析的全生命周期：

### 1. 🔁 事务内重复 SQL (N+1) 诊断 (默认首页)
- **精准事务粒度**：基于日志中的 `dbManager` 内存对象句柄（如 `MySqlDBManager@7b2aa7e0`），只抓取在【同一数据库事务内】重复执行的 SQL 模板，彻底排除跨请求/跨事务的误报。
- **自定义阈值**：支持**自由手填重复次数阈值（`>= N 次`）**，实时动态筛选。
- **重构建议与下钻**：自动判定严重等级（如推荐 `IN(...)` 批量化或二级缓存），提供「🔍 查看调用」一键跳转至完整调用明细。

### 2. 🐢 慢 SQL 排行
- **耗时降序呈现**：按单次执行耗时降序排列，快速定位拖慢系统响应的瓶颈 SQL。
- **灵活阈值**：支持**自由手填耗时阈值（`>= N ms`）**过滤。
- **代码直达**：每一条慢 SQL 均提供 `📎 file:line` 链接，点击瞬间唤起 VSCode 高亮定位至日志所在行。

### 3. 🔗 Trace 链路分析
- **全序列还原**：完整还原单次请求生命周期内的全部 SQL 执行序列（默认 50 条/页）。
- **原生时间顺序**：严格按日志真实时间顺序展示单次 Trace 的完整上下文流程。
- **行号与路径**：完整输出日志文件的绝对路径和所在行号，支持一键在 VSCode 中高亮打开。

### 4. 📊 SQL 频次榜
- **全库归一化聚合**：自动对全库参数化 SQL 模板进行归一化频次与耗时统计，汇总全局执行总次数、总耗时、平均耗时、最大耗时与涉及 Trace 数。
- **下钻明细**：点击「🔍 查看调用」即可调出该模板在全库中的每一笔具体执行调用记录。

### 5. 📋 SQL 调用明细
- **全上下文追溯**：展示指定 SQL 模板在全库中的每一笔具体调用记录，顶部动态呈现过滤上下文标签（准确标注来源：频次榜或 N+1 诊断、TraceID、dbManager 事务句柄 Hash 及循环次数）。
- **行号与路径**：完整输出日志文件的绝对路径和所在行号，支持一键在 VSCode 中高亮打开。

### 6. 📈 概览统计分析
- 汇聚分析 SQL 总数、归一模板数、最高慢 SQL 耗时、独立 Trace 动作数、总耗时以及文件扫描解析性能指标。

## ⚡ 性能与技术架构

- **C++ 向量执行**：底层依赖 **DuckDB 纯内存引擎**，全量数据在内存进行 Multi-row Chunk 向量化装载与聚合，查询耗时通常 $< 50\text{ms}$。
- **多核 Worker Threads**：面对超大日志文件或日志目录，自动启用多核子进程并行切块解析，充分吃满 CPU 性能。
- **智能列名折叠**：针对上百列的超长 `SELECT` 语句，前端 0ms 瞬间折叠为 `select ... from <表与条件>`，兼顾可读性与浏览效率。
