# 代码修改与测试约束规则 (Test Discipline Rule)

## 规则内容
1. **修改重要代码必增测试**：在修改或新增任何核心功能、算法、逻辑（如解析器、数据处理、API 等重要代码）后，必须在 `test/` 目录下添加或更新相应的单元测试用例。
2. **修改代码后必执行测试**：无论修改大小，修改代码后必须运行 `npm test`（或相应的测试命令），验证所有测试 100% 绿灯通过后方可交付。
3. **禁止直接 push，仅限本地提交**：修改代码并通过测试后，仅在本地进行 `git commit` 提交，严禁自动执行 `git push` 推送到远程仓库，由用户决定何时手动 push。
4. **非必要不修改原有测试用例**：严禁随意删改、覆盖或直接修改已有的正常测试用例；遇到新需求、边界反例或 Bug 修复时，**必须优先在测试文件中【新增独立的测试用例】**，确保重构与新代码绝不会破坏旧功能的测试回归。
